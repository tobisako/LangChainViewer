# サンプルデータの作り方

このリポジトリに入っているデータは **`tools/make_sample_data.py` が乱数で生成したもの**です。
外部から持ち込んだデータは1件も含まれません。乱数の種を固定しているので、
誰が実行しても同じデータになります。

## 1. どのテーブルがあるか

テーブルは全部で **3つ** です。

| テーブル | 件数 | 役割 |
|---|---|---|
| `lead_plot_out` | 6,689 | 出力用。1行が1件の見込み客 |
| `lead_plot_agg` | 6,689 | 集計用。`lead_plot_out` と**同一構造・同一件数** |
| `m_property` | 300 | 物件マスタ。物件コードと所在地・価格帯・建物面積 |

`lead_plot_out` と `lead_plot_agg` を分けているのは、実務では出力用と集計用で
更新のタイミングが違うためです。このサンプルでは同じ中身を入れています。

## 2. テーブルの結合

`lead_plot_out`（または `lead_plot_agg`）と `m_property` は
**`object_code` 列**で結合します。両方のテーブルに同じ物件コードが入っています。
`formal_object_name` は `m_property` から写した冗長列なので、結合キーには使いません。

## 3. 列の意味（主なもの）

| 列 | 意味 |
|---|---|
| `pid` | 見込み客の識別子 |
| `address1`〜`address4_1` | 都道府県・市区・町名・番地 |
| `recognition_media` | 何で知ったか（折込チラシ／Web検索／紹介／SNS広告 ほか） |
| `budget_price` | 予算（万円） |
| `hope_building_area` | 希望建物面積 |
| `contract_generations` | 契約世代（20〜70） |
| `reaction_flg` / `visitor_flg` / `contractor_flg` | 反響・来場・契約の有無 |
| `zip_code` / `birthday` / `latitude` / `longitude` / `ma_lead_id` | 個人を特定しうる列 |

最後の行の5列は、**意図的に残してあります**。
安全機構（個人情報の要求を拒否する層）が働くかどうかを試すために必要だからです。

## 4. このサンプルで再現していない処理

実務のデータ基盤にはあるが、**このサンプルでは再現していない**処理があります。

- **クレンジング**（表記ゆれの統一、住所の正規化、重複の名寄せ）
- **参照元システムからの取り込み**（外部システムの実データを写す工程）
- 差分更新・履歴管理（このサンプルは毎回まるごと作り直す）

`duplicated_flag_ma` 列は名寄せの結果を入れる想定の列ですが、
値は乱数で入れているだけで、実際の重複判定は**加工していません**。
